# HAVEX — сайт PPF бронеплёнок

Премиальный лендинг бренда **HAVEX** (полиуретановые бронеплёнки PPF) с приёмом
заявок, которые уходят напрямую в чат Telegram.

## Быстрый старт

```bash
cd havex-site
npm install
cp .env.example .env     # затем заполните .env
npm start                # → http://localhost:3000
```

Режим разработки с автоперезапуском: `npm run dev`

## Подключение Telegram (обязательно для приёма заявок)

Пока `.env` не заполнен, сайт работает полностью, но форма отвечает
«Приём заявок временно недоступен», а заявка печатается в консоль сервера —
удобно для проверки вёрстки без бота.

### 1. Создайте бота
Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен вида
`1234567890:AAH...`

### 2. Узнайте chat_id
Напишите своему боту любое сообщение, затем откройте в браузере:

```
https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates
```

Найдите `"chat":{"id":123456789}` — это и есть `TELEGRAM_CHAT_ID`.

Для группы: добавьте бота в группу, напишите туда сообщение и возьмите id
из `getUpdates` (id группы начинается с `-100`).

### 3. Заполните `.env`

```env
TELEGRAM_BOT_TOKEN=1234567890:AAH...
TELEGRAM_CHAT_ID=123456789
PORT=3000
```

Перезапустите сервер. В консоли появится `Telegram: подключён ✓`.

Проверить статус: `GET /api/health` → `{"ok":true,"telegram":true}`

## Демо на GitHub Pages (временная ссылка)

Если нужна публичная ссылка для показа клиенту, сайт можно опубликовать на
GitHub Pages. Важно: Pages отдаёт **только статику**, поэтому опубликованный
сайт — это демо без приёма заявок (нет Node, нет `.env`, нет `/api/lead`).
Форма на демо показывает сообщение «это демо-версия», а не ломается.

### Как включить (один раз)

1. Откройте https://github.com/Sargis7/havexppf/settings/pages
2. **Source** → выберите **GitHub Actions** (не «Deploy from a branch»)
3. Сделайте любой коммит в `main` — или запустите workflow вручную:
   **Actions** → *Deploy demo to GitHub Pages* → **Run workflow**

Через 1–2 минуты сайт появится по адресу:

```
https://sargis7.github.io/havexppf/
```

### Что именно публикуется

Workflow `.github/workflows/pages.yml` собирает отдельную папку `_site` и
кладёт туда только статические файлы — `server.js`, `.env`, `_admin/` и
`node_modules` в публикацию не попадают:

```
_site/
├── index.html     ← редирект на demo.html
├── demo.html      ← сам сайт + плашка «ДЕМО»
├── styles.css, app.js, favicon.svg
├── data/catalog.js
└── assets/*       ← картинки
```

`demo.html` — копия лендинга с относительными путями и без
`window.HAVEX_API`, поэтому форма знает, что бэкенда нет. Если поменяете
`public/index.html`, не забудьте обновить `demo.html` (или просто скопируйте
его поверх и верните плашку).

### Как отключить

**Settings → Pages → Unpublish site** — ссылка перестанет открываться.
Альтернатива без включения Pages: временный туннель к локальному серверу,
например `npx localtunnel --port 3000` или `ngrok http 3000` — тогда работает
и форма с Telegram, пока ваш компьютер включён.

## Админ-панель

Открывается по адресу **http://localhost:3000/adminpanel/** (либо `/admin`,
`/adminpanel.html` — они перенаправляют туда же).

**Пароль хранится только на сервере, в переменных окружения.** В коде его нет
ни в открытом виде, ни хешем — в браузер он не попадает вообще.

Задайте в `.env` (или в Variables на Railway):

```env
ADMIN_PASSWORD=ваш-пароль-минимум-12-символов
ADMIN_SESSION_SECRET=<openssl rand -hex 32>
ADMIN_SESSION_HOURS=12
```

Сгенерировать секрет:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

`ADMIN_SESSION_SECRET` подписывает cookie сессии (HMAC-SHA256). Если его не
задать, сервер сгенерирует случайный при старте — тогда все сессии слетают при
каждом рестарте или деплое. Если не задан `ADMIN_PASSWORD` — вход заблокирован
и в консоли появится предупреждение.

Как это устроено:

- `POST /api/admin/login` сверяет пароль через `timingSafeEqual` и выдаёт
  `HttpOnly; SameSite=Strict` cookie на `ADMIN_SESSION_HOURS` часов.
- `GET /adminpanel/` и все файлы панели отдаются только при валидной подписи
  cookie. Без неё вместо панели приходит страница входа (статус 401).
- Запросы к `/api/admin/login` ограничены: 8 попыток за 15 минут на IP.
- `POST /api/admin/logout` гасит cookie. Кнопка «Выйти» в панели зовёт его.

Пароль меняется правкой `ADMIN_PASSWORD` и рестартом сервиса. В браузере ничего
менять не нужно.

### Подключение к GitHub

Панель пишет изменения прямо в репозиторий, поэтому ей нужен токен:

1. https://github.com/settings/personal-access-tokens/new
2. **Repository access** → *Only select repositories* → `havexppf`
3. **Permissions** → Repository permissions → **Contents: Read and write**
4. Сгенерировать и вставить в панели

Токен хранится только в `localStorage` вашего браузера и отправляется
исключительно на `api.github.com`. В репозиторий он не попадает.

### Возможности

| Вкладка | Что делает |
|---|---|
| **Товары** | добавление, редактирование и удаление позиций каталога; фото загружается в `public/assets/products/` |
| **Примеры работ** | загрузка фото в `public/assets/gallery/`, подписи, удаление; блок на сайте включается автоматически |
| **Видео** | список роликов (YouTube, VK Video, mp4) с названием и превью |
| **Контакты** | телефон, email, график, ссылки на Instagram / Telegram / YouTube |
| **Тексты сайта** | заголовок героя в три строки, подзаголовок, заголовок и описание блока работ, показ блока работ |

Все данные лежат в **`public/data/catalog.js`** — один файл на весь контент.
Панель перечитывает его `sha` перед каждой записью, поэтому параллельные
правки не затираются: при конфликте выйдет сообщение «Файл изменился на
GitHub». Загрузка фото сжимает изображение до 1600 px по длинной стороне
(JPEG q0.85), чтобы не раздувать репозиторий.

### Ручное редактирование каталога

`public/data/catalog.js` — обычный JS-файл, его можно править руками:

```js
window.HAVEX_DATA = {
    updated: '2026-11-16',
    settings: { phone: '+7 (800) 000-00-00', /* ... */ },
    products: [
        {
            code: 'HX-PPF-GL5',
            name: 'Gloss Guard 200',
            accent: '#8CD117',
            tag: 'Хит продаж',
            tagAlt: false,
            desc: 'Базовый глянцевый PPF...',
            specs: [['Толщина', '200 мкм']],
            price: 24900,
            unit: 'рулон',
            image: '',        // пусто = фирменная «коробка» на CSS
            hidden: false
        }
    ],
    gallery: [{ src: 'assets/gallery/rabota-1.jpg', title: 'BMW X5' }],
    videos : [{ title: 'Оклейка за 1 день', url: 'https://youtu.be/...' }]
};
```

Файл подключается в `index.html` **до** `app.js`, поэтому весь контент
рендерится на клиенте, а сам сайт остаётся статикой.

### Безопасность панели

Панель отдаётся с `X-Robots-Tag: noindex, nofollow, noarchive`, закрыта в
`robots.txt` и исключена из выдачи.

Пароль проверяется **на сервере**, в коде сайта его нет. До входа сервер не
отдаёт ни страницу панели, ни `admin.js`, ни остальные её файлы — только форму
входа. Cookie сессии помечена `HttpOnly` (её не прочитает JS) и `SameSite=Strict`
(не уедет на другой сайт), подписана HMAC-SHA256 и живёт ограниченное число часов.
Частота попыток входа ограничена, поэтому перебор пароля нереалистичен.

Второй рубеж — токен GitHub с правом записи только в этот репозиторий: даже
получив доступ к панели, дальше этого репозитория уйти не получится.

Если нужен ещё один слой, панель можно дополнительно закрыть HTTP Basic Auth
на уровне nginx или Cloudflare Access — но при текущей схеме это уже
необязательно:

```nginx
location /adminpanel/ {
    auth_basic "HAVEX admin";
    auth_basic_user_file /etc/nginx/.htpasswd;
    proxy_pass http://127.0.0.1:3000;
}
```

## Соцсети

Ссылки в блоке контактов, футере и плавающая кнопка Telegram в правом нижнем
углу. Меняются во вкладке **Контакты** админ-панели или прямо в
`public/data/catalog.js` (`settings.instagram`, `settings.telegram`,
`settings.youtube`).

## Что защищено в форме

- валидация на клиенте и на сервере (имя, телефон ≥10 цифр, формат email)
- honeypot-поле `company` — боты получают «успех», но заявка не уходит
- ограничение частоты: 12 заявок на IP за 10 минут
- лимит размера тела запроса 32 КБ
- HTML-экранирование всех полей перед отправкой в Telegram

## Продакшн

Сервер слушает `PORT` и доверяет заголовку `X-Forwarded-For` (для корректного
определения IP за прокси). Запускайте под `pm2`/`systemd` и поставьте перед ним
nginx с HTTPS. Никогда не коммитьте `.env` — он уже в `.gitignore`.
